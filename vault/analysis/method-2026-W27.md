# 방법 렌즈 분석 — 2026-W27

> source-grounding 원칙 적용: 원문(초록·검색 결과) 밖 지식·추론에는 `해석:` / `외부 맥락:` / `추정:` / `미제공:` / `질문:` / `검토필요:` prefix를 붙인다. arXiv.org 직접 접근이 정책상 차단되어 초록·웹 검색 결과 기반으로 분석하며, 방법 섹션 세부 정보에 한계가 있는 부분은 명시한다.

## 총평

이번 주 5편은 세 가지 방향으로 갈린다. 첫째, LLM을 문헌 지식 추출 파이프라인으로 쓰는 흐름(Affinage, Active-GRPO)이 나란히 등장했다 — 하나는 생물학 지식 베이스 구축에, 다른 하나는 분자 최적화 추론에 LLM을 활용한다. 둘째, 고차원·소표본 데이터라는 오믹스 분류의 고질적 병목을 정공법으로 다루는 시도가 두 편(CNS 메틸화 분류, 구조화 GP) 들어왔다. 셋째, 해석 가능성을 모델 설계에 내장하려는 움직임(MLP-GNN 수용해도 분해)이 신약 AI 쪽에서도 나타난다. 공통 신호: 성능 향상 자체보다 "왜 이 예측이 나왔나"를 설명하고 재사용 가능한 자원을 남기려는 설계 방향이 강해지고 있다.

## 1. Affinage: 게놈 규모 메커니즘 유전자 주석

**arXiv**: https://arxiv.org/abs/2607.02217  
**저자**: Matteo Di Bernardo, Iain M. Cheeseman (Whitehead Institute for Biomedical Research & MIT Department of Biology)  
**상태**: preprint (미동료심사), 2026-07-02  
**코드·데이터**: 코드 공개 — https://github.com/cheeseman-lab/affinage | 주석 데이터·REST API·MCP 서버 — https://affinage.wi.mit.edu

---

**문제의식 선행**

인간 단백질 코딩 유전자 19,293개 중 상당수는 UniProt 기능 항목이 비어 있거나 수년 된 문헌에만 근거한다. 논문 수는 PubMed에 2,000만 편 이상이지만 이를 유전자당 구조화 형태로 집약하는 자동화된 수단이 없었다. Affinage는 이 간극을 1차 문헌에서 직접 채우는 파이프라인이다.

**무엇이 새로운가**

- 기존 LLM 기반 유전자 주석 시도 대부분은 모델 내부 지식(파라미터 기억)에 의존하거나 범용 RAG(Retrieval-Augmented Generation)를 그대로 적용했다. Affinage는 두 단계를 분리한다. **읽기 패스(reading pass)**는 1차 문헌에서 직접 실험 증거만 추출하고(간접 추론·리뷰 제외), **합성 패스(synthesis pass)**는 읽기 패스가 모은 증거만을 대상으로 추론한다. 외부 지식 오염을 차단하는 설계다.
- 유전자당 한 번 실행하고 결과를 구조화 레코드로 캐싱(저장)한다 — 매번 재쿼리가 필요 없다.
- Claude Sonnet 4.6(읽기 패스)과 Claude Opus 4.8(합성 패스)을 조합해 비용·품질을 분리 최적화했다. (검색 결과 기반 수치; 초록에는 모델명 미명시 — `검토필요:` 원문 방법 섹션 직접 확인 권장)
- 결과물(19,293개 유전자 주석 + REST API + MCP 서버)을 오픈 배포해 즉시 다운스트림 활용이 가능한 자원으로 남긴다.

**메커니즘 핵심 가정**

1. 1차 문헌에 직접 실험 증거가 충분히 존재한다면, LLM이 해당 증거만으로 정확한 메커니즘 기술을 생성할 수 있다.
2. 읽기 패스가 간접 추론·리뷰·이차 자료를 걸러낸다는 전제가 실제로 성립해야 한다(프롬프트 설계의 엄밀성에 달림).
3. 크로스-패밀리 LLM 판사 비교가 품질 기준으로 타당하다는 가정 — 즉, "다른 LLM이 더 낫다고 판단"이 실제 생물학적 정확도와 상관한다는 보장이 필요하다.

**데이터**: 19,293개 인간 단백질 코딩 유전자. 비교 기준 데이터: UniProt 기능 항목.

**코드·재현성**: 코드 공개(GitHub). 프롬프트 버전도 릴리스에 포함한다고 보고 (검색 결과 기반). 2026년 5월 주석 완료; 코드 재실행으로 재현 가능하다고 저자 주장. 재현 비용(API 호출 비용)은 `미제공`.

**베이스라인 대비 성능**: 크로스-패밀리 LLM 판사 기준 head-to-head 비교에서 UniProt 기능 항목 대비 **99.1%에서 Affinage 주석이 우위**를 기록했다고 보고 (초록 기준). `해석:` "우위"의 기준이 LLM 판사라는 점에 주의 — 인간 전문가 평가나 실험 검증이 아니다. 평가 설계의 순환 참조 위험(LLM이 LLM 결과를 평가) 여부는 방법 섹션 확인 필요.

**강점**

- 코드·데이터·REST API 전체 공개 — 바이오인포 연구자가 즉시 파이프라인에 통합 가능.
- UniProt 미등재 또는 빈 유전자에 메커니즘 기술을 제공하는 실질적 자원 가치.
- 읽기·합성 패스 분리는 RAG 대비 오염 제어 측면에서 설계상 진보.

**한계**

- `해석:` 평가 지표가 LLM 판사에 국한 — 생물학 전문가에 의한 무작위 샘플 검증 데이터가 있는지 초록 수준에서 불명확. 검증 수준이 (in silico) 범위를 벗어나지 않는다.
- 읽기 패스 정밀도(실험 증거로 잘못 분류된 리뷰 기반 기술 비율)에 대한 정량 평가가 초록에 미제공.
- `질문:` 잘 알려지지 않은 유전자(문헌이 3편 미만인 경우)에서 품질이 어떻게 저하되는가?
- `질문:` API 접근 의존 파이프라인이므로 LLM 모델 버전 갱신 시 주석 재현성이 달라질 수 있다.

**내 연구에의 적용**: 멀티오믹스 분석 파이프라인의 유전자 기능 주석 단계에서 UniProt/GO 대체 또는 보완 레이어로 즉시 사용 가능하다. REST API와 MCP 서버를 통해 기존 워크플로에 삽입하기 쉽다. 단, LLM 판사 평가 한계를 인식하고 핵심 타깃 유전자는 원문 문헌을 교차 확인할 것.

**검증 수준**: (in silico) — LLM 판사 기반 비교. 실험적 검증 없음.

## 2. DNA 메틸화 기반 CNS 종양 91클래스 분류

**arXiv**: https://arxiv.org/abs/2607.01307  
**저자**: Paulo R. Ferreira Jr., Lucas Coutinho Freitas 외 5인 (Universidade Federal de Pelotas & Hospital de Clínicas de Porto Alegre, Brazil)  
**상태**: preprint (미동료심사), 2026-07-01  
**코드·데이터**: `미제공` — 초록·검색 결과에서 GitHub/Zenodo 링크 미확인

---

**문제의식 선행**

Capper 등(2018) DKFZ 분류기는 CNS 종양 DNA 메틸화 기반 분류의 사실상 표준이지만, 클래스가 확장되면서 기존 방법의 전이 가능성과 공정한 다중클래스 평가 방식에 의문이 제기되어 왔다.

**무엇이 새로운가**

- 기존 DKFZ 분류기(랜덤 포레스트 기반)를 대체하는 방향보다, **방법론 선택의 재검토**에 집중한다 — Sparse Random Projection(SRP)으로 고차원 메틸화 배열(수십만 CpG 사이트)의 차원을 축소하고, 다항 로지스틱 회귀(multinomial logistic regression)로 분류하는 단순하지만 검증 가능한 파이프라인을 제안한다.
- 독립 임상 평가 코호트(1,104건)를 별도로 사용해 내부 교차검증과 외부 검증을 분리한다는 점이 방법론 엄밀성 측면에서 중요하다.
- 91클래스라는 세밀한 분류 수준에서 평가한 점 — 기존 논문 중 이 클래스 수에서 공정하게 평가한 사례가 드물다.

**메커니즘 핵심 가정**

1. SRP로 차원을 축소해도 91클래스 분류에 필요한 판별 정보가 보존된다(Johnson-Lindenstrauss 보조정리 기반 가정).
2. 참조 코호트(2,801건)와 평가 코호트(1,104건)의 배치 효과(batch effect)가 충분히 통제되어 있어야 클래스 수준 개선이 방법론 자체의 공로다.
3. `해석:` 로지스틱 회귀의 선형 결정 경계가 메틸화 프로파일 공간에서 91클래스를 분리하기에 충분하다는 가정 — 드물거나 중간적인 메틸화 표현형에서는 약점이 될 수 있다.

**데이터**: 참조 코호트 2,801건(층화 3-fold 교차검증) + 독립 임상 평가 코호트 1,104건. 데이터 출처(DKFZ 공개 데이터셋 여부, GEO accession 등)는 `미제공`.

**코드·재현성**: `미제공` — 코드 공개 여부 미확인. 재현성 검증이 현재로선 어렵다.

**베이스라인 대비 성능** (초록 기준):
- 독립 평가 코호트 91클래스 수준 정확도: **86%** (기존 SOTA 참조 수치 82% 대비 +4 pp 절대 개선)
- 메틸화 클래스 패밀리 수준: **93%** (기존 88% 대비 +5 pp)
- 참조 코호트 내부 교차검증 평균 정확도: **96%**

`검토필요:` "기존 SOTA 참조 수치"의 정확한 출처(Capper 2018인지, 최근 업데이트 분류기인지)를 본문에서 확인할 필요가 있다. 방법·평가 프로토콜이 완전히 동일한 조건에서 비교된 것인지 초록 수준에서 단정할 수 없다.

**강점**

- 독립 임상 평가 코호트 설계 — 내부 과적합 위험을 낮춘다.
- SRP + 로지스틱 회귀는 해석 가능성이 높고 배포가 용이하다.
- 91클래스 전체 평가라는 점에서 기존 분류기와의 공정한 비교 틀을 제시한다.

**한계**

- 코드 미공개(현재 기준) — 독립 재현이 불가하다.
- `추정:` 훈련 데이터가 DKFZ 공개 데이터셋에서 왔다면, 평가 코호트도 같은 기관 데이터일 가능성이 있어 진정한 "외부" 검증 여부 확인 필요.
- 소수 클래스(rare methylation class) 성능이 평균 정확도에 희석될 수 있다 — 클래스별 성능 분포 데이터가 초록에 없다.
- `질문:` 칼리브레이션(calibration) 성능은 보고되었나? 임상에서 "예측 불확실성"이 중요한 맥락에서 신뢰 점수의 신뢰도가 관건이다.

**내 연구에의 적용**: 임상 ML 파이프라인에서 고차원 오믹스의 차원 축소+분류기 조합으로 SRP+로지스틱 회귀를 적극 검토할 수 있다. 특히 샘플 수가 수천 이하인 다중클래스 문제에서 복잡한 딥러닝 대비 실용적 대안이다. 단, 코드가 공개되면 재현 실험 후 도입을 권장한다.

**검증 수준**: (후향, N=1,104 독립 코호트) — 단일 기관 또는 단일 데이터셋 기반 여부는 `미제공`.

## 3. Active-GRPO: 분자 최적화를 위한 능동적 모방-자기발견 강화학습

**arXiv**: https://arxiv.org/abs/2607.00531  
**저자**: Xuefeng Liu, Mingxuan Cao, Qinan Huang, Thomas Brettin, Rick Stevens, Le Cong (Stanford University; University of Chicago; Argonne National Laboratory)  
**상태**: preprint (미동료심사), 2026-07-01  
**코드·데이터**: `미제공` — 검색 결과에서 GitHub 링크 미확인

---

**문제의식 선행**

LLM 기반 분자 최적화에서 SFT는 다단계 추론 능력을 붕괴시키고, 순수 RLVR은 보상 신호가 희소해 탐색이 어렵다. 기존 RePO는 고정된 참조 분자에 성능 상한이 묶인다는 구조적 한계가 있었다.

**무엇이 새로운가**

- **기존 GRPO·RePO와의 결정적 차이**: RePO는 참조 분자를 고정하고 모방과 강화를 일괄 적용한다. Active-GRPO는 인스턴스별로 "지금 참조가 정책보다 좋은가"를 판단해 모방(imitation) 또는 자기발견(self-reinforcement)을 동적으로 전환하고, 정책이 참조를 넘어서면 새 참조를 정책 최고 후보로 자동 갱신한다.
- **두 메커니즘의 결합**:
  - *Active imitate-reinforce*: 참조가 정책 후보보다 우수할 때만 모방 학습을 수행 → 과모방(over-imitation)을 방지.
  - *Active referencing*: 학습 중 최고 후보가 기존 참조를 능가하면 참조를 갱신 → 고정 상한 문제를 해소.
- 이 둘의 조합이 RePO의 "참조 품질 의존" 문제를 구조적으로 해결하려는 시도다.

**메커니즘 핵심 가정**

1. 인스턴스별 비교 신호(정책 vs. 참조 품질)가 신뢰할 수 있고 계산 가능해야 한다 — 분자 유사도·성질 평가 함수의 품질이 전체 루프의 병목이 된다.
2. 참조 갱신이 학습 안정성을 훼손하지 않아야 한다 — 참조가 급격히 바뀌면 학습 신호가 흔들릴 수 있다.
3. `해석:` SRxSim(성공률 × 유사도) 지표가 실제 신약 개발에서 의미 있는 최적화 목표와 충분히 상관해야 한다. LogP·MR·QED는 계산 지표이며 in vitro/in vivo 활성과의 간극이 크다.

**데이터**: TOMG-Bench MOLOPT 벤치마크. 3-seed 평가.

**코드·재현성**: `미제공` — 코드 공개 여부 미확인. 3-seed 평가로 랜덤성 일부 통제.

**베이스라인 대비 성능** (초록 기준, 3-seed 평균):
- GRPO: SRxSim = 0.0959
- RePO: SRxSim = 0.1665
- **Active-GRPO: SRxSim = 0.1773** (+6.5% vs. RePO)
- LogP, MR, QED 각 항목에서 통계적으로 유의한 개선 보고.

`해석:` RePO 대비 개선폭(0.1665 → 0.1773)은 절대값으로 약 6.5% 향상으로 작지 않지만, TOMG-Bench 단일 벤치마크에 국한된 결과다. 다른 분자 최적화 벤치마크나 실제 약물 설계 시나리오로의 일반화 여부는 별도 검증이 필요하다.

**강점**

- 능동적 전환 메커니즘은 고정 참조 의존 문제를 설계 수준에서 다루는 아이디어로, RLVR 분자 최적화 분야에 확장 가능하다.
- 통계 검증(3-seed, 유의성 보고)을 포함한 점.

**한계**

- 코드 미공개(현재 기준) — 재현 검증 불가.
- 단일 벤치마크(TOMG-Bench MOLOPT) 평가 — 다양한 분자 최적화 과제로의 일반화 여부 불명확.
- 기반 LLM 모델 명시 여부가 초록 수준에서 불명확 — `미제공`. 어떤 LLM 위에서 파인튜닝하는지가 재현과 적용에 결정적이다.
- `질문:` 참조 갱신 빈도·기준이 하이퍼파라미터로 민감한가? 그 민감도 분석이 있는가?
- LogP·MR·QED는 계산 가능 지표 — in vitro 활성, 독성, ADME와의 연결은 별도 검증이 필요하다.

**내 연구에의 적용**: 분자 최적화 프레임워크 설계 시 "참조 갱신 + 동적 모방/탐색 전환" 패턴은 재사용 가능한 RL 학습 루프 설계 원리로 참고할 가치가 있다. 그러나 코드가 공개되고 다양한 분자 설계 과제에서 검증될 때까지 직접 사용 도입은 보류를 권장한다.

**검증 수준**: (in silico) — TOMG-Bench 계산 벤치마크만.

## 4. 구조화 가우시안 프로세스(GP)를 이용한 불확실성 인식 오믹스 분류

**arXiv**: https://arxiv.org/abs/2607.02103  
**저자**: Yue Zhang, Nandini Amit Gadhia, Georgios Karagiannis, Michalis Smyrnakis (Durham University; STFC Hartree Centre, University of Liverpool & Daresbury Laboratory)  
**상태**: preprint (미동료심사), 2026-07-02  
**코드·데이터**: `미제공` — 검색 결과에서 공개 코드 링크 미확인. 3개 공개 마이크로바이옴 데이터셋 사용.

---

**문제의식 선행**

오믹스 데이터는 특성(feature) 수가 샘플 수를 수십~수백 배 초과하는 p >> n 문제, 비선형 상호작용, 클래스 불균형이 동시에 발생한다. 기존 ML은 이 세 가지를 함께 처리하면서 생물학적으로 해석 가능한 불확실성을 제공하지 못했다.

**무엇이 새로운가**

- 생물학적 경로(pathway) 네트워크를 그래프로 인코딩하고, 이를 GP 커널(kernel) 구성에 직접 통합한다. 단순히 그래프 정보를 입력 피처로 쓰는 GNN 방식과 달리, **커널 수준에서 생물학적 위상(topology)을 반영**한다는 점이 구조적으로 다르다.
- 풍부도(abundance) 파생 피처와 경로 그래프 전파 정보를 결합해 정량적 측정값과 위상 맥락을 동시에 포착한다.
- 클래스 불균형 대응 전략(데이터 레벨 리샘플링, 임계값 보정, 혼동행렬 기반 조정)을 체계적으로 비교 평가한 점.
- GP의 구조적 장점인 **불확실성 정량화(uncertainty quantification)**를 고차원 오믹스 분류에 연결 — 예측 신뢰도를 함께 제공한다.

**메커니즘 핵심 가정**

1. 사용되는 생물학적 경로 네트워크가 해당 데이터의 생물학적 실체를 올바르게 반영해야 한다 — 경로 데이터베이스(KEGG, Reactome 등) 자체의 불완전성이나 맥락 특이성이 커널 품질을 직접 제약한다.
2. GP의 확장성 — 표준 GP는 O(N³) 복잡도를 가지므로 샘플 수 증가 시 계산 비용이 급증한다. 고차원이지만 소표본이라는 오믹스 특성에 딱 맞는 설정이나, 샘플이 늘어나면 확장이 어렵다.
3. `해석:` 경로 그래프를 커널에 통합하는 방식이 실제로 일반화(generalization) 향상에 기여한다는 것은 검증 데이터셋과 경로 데이터의 정합성에 달린다. 마이크로바이옴 데이터셋에서만 검증된 점은 다른 오믹스 유형으로의 일반화에 물음표를 남긴다.

**데이터**: 3개 공개 장·대변 마이크로바이옴 데이터셋 (데이터셋명·GEO accession 미제공 — `미제공`).

**코드·재현성**: `미제공` — 공개 코드 확인 불가. 공개 데이터셋을 사용했으므로 코드가 공개되면 재현 시도 가능.

**베이스라인 대비 성능**: 구체적 수치는 초록 수준에서 미제공. "비구조화 베이스라인 대비 성능 향상, 유사 데이터셋의 기존 벤치마크와 동등"이라는 정성적 보고만 확인됨 (`검토필요:` 구체 수치는 본문 확인 필요).

**강점**

- 생물학 사전 지식을 커널에 내장하는 방식은 p >> n 오믹스 문제에 이론적으로 타당한 귀납적 편향(inductive bias)을 제공한다.
- 불확실성 정량화 포함 — 임상 의사 결정 지원 시스템에서 "예측 불확실" 샘플을 걸러내는 데 활용 가능.
- 클래스 불균형 전략 비교 분석이 실용적 가이드를 제공한다.

**한계**

- 코드 미공개(현재 기준).
- 3개 마이크로바이옴 데이터셋만 검증 — 전사체, 단백질체, 임상 메타게놈 등 다른 오믹스 유형으로의 일반화 미검증.
- GP 확장성 문제: 샘플 수가 수천을 넘으면 계산 비용이 급격히 증가한다. 코호트가 커지는 임상 오믹스 환경에서 실용성이 제한될 수 있다.
- `질문:` 경로 네트워크 선택(KEGG vs. Reactome vs. STRING)이 결과에 얼마나 민감한가?
- `추정:` 마이크로바이옴 분류라는 특정 도메인에서는 경로 커널이 효과적일 수 있으나, 경로가 덜 확립된 오믹스 데이터(단세포 전사체 신규 세포 유형 등)에서는 커널 설계 자체가 어려울 수 있다.

**내 연구에의 적용**: 소규모(N < 500) 고차원 오믹스 분류 과제에서 불확실성 추정이 필요한 경우, SVM·랜덤 포레스트 대비 구조화 GP를 비교 실험할 가치가 있다. 경로 데이터베이스가 충분히 정립된 질환 도메인(예: 대사 증후군, 장내 미생물 관련 질환)에서 우선 적용을 검토할 수 있다. 코드 공개 시 우선 확인 대상.

**검증 수준**: (in silico, 공개 데이터셋 벤치마크)

## 5. MLP-GNN 덧셈 프레임워크: 수용해도 예측의 화학·구조 기여 분해

**arXiv**: https://arxiv.org/abs/2607.02212  
**저자**: Sampreeti Bhattacharya, Arkaprava Roy (University of North Carolina; University of Florida)  
**상태**: preprint (미동료심사), 2026-07-02  
**코드·데이터**: `미제공` — GitHub 링크 미확인. AqSolDB 및 BigSolDB2는 공개 데이터셋.

---

**문제의식 선행**

수용해도 예측 모델 대부분이 물리화학적 기술자와 분자 그래프 정보를 단일 표현으로 병합한다. 예측이 전역 화학 특성에서 온 것인지 분자 위상 구조에서 온 것인지 사후에 분리할 수 없다는 것이 기존 한계였다.

**무엇이 새로운가**

- **아키텍처 설계 자체가 해석 가능성의 도구가 된다.** 물리화학적 기술자(MLP 화학 브랜치)와 분자 그래프 위상(GNN 구조 브랜치)을 독립 학습하고 예측 단계에서만 덧셈(additive)으로 결합 — 두 브랜치가 기여하는 수용해도 성분을 사후에 분리 검토할 수 있다.
- 선택적 곱셈 상호작용(multiplicative interaction) 항을 추가해 화학-구조 결합 효과도 포착할 수 있다.
- 대규모 AqSolDB 사전학습 + 소규모 BigSolDB2 파인튜닝 — 데이터 규모가 다른 두 데이터셋을 이단계로 활용하는 전략.
- GNNExplainer 마스크를 원자 단위(atom-level)로 집계해 기능기(functional group)별 기여도를 시각화한다.

**메커니즘 핵심 가정**

1. 화학 특성과 구조적 위상이 실제로 독립적인(또는 약하게 상관된) 수용해도 기여 요인이라는 가정 — 덧셈 모델이 성립하려면 두 브랜치 간 독립성이 어느 정도 성립해야 한다. 곱셈 상호작용 항이 이 가정을 완화하지만 완전히 해소하지는 않는다.
2. AqSolDB에서 학습한 표현이 BigSolDB2의 다른 조건(다른 용매·온도 범위 등)에도 전이된다는 가정 — `외부 맥락:` BigSolDB2(BigSolDB 2.0)는 유기 화합물의 다양한 용매·온도에서의 용해도 데이터셋으로 AqSolDB와 측정 조건이 부분적으로 다를 수 있다.
3. GNNExplainer 마스크가 실제 화학적으로 의미 있는 원자 기여도를 반영한다는 가정 — `해석:` GNNExplainer는 국소 근사 방법으로, 설명의 충실도(faithfulness)는 별도 검증이 필요하다.

**데이터**: AqSolDB(사전학습, 공개 대규모 수용해도 DB) + BigSolDB2(파인튜닝, 공개). 구체 샘플 수는 `미제공` (초록 수준).

**코드·재현성**: `미제공` — 코드 공개 여부 미확인. 두 데이터셋 모두 공개이므로 코드가 공개되면 재현 시도 가능.

**베이스라인 대비 성능**: 구체 수치는 초록 수준에서 미제공. "사전학습+파인튜닝이 정확도와 run-to-run 안정성을 실질적으로 개선"이라는 정성적 보고. `검토필요:` 비교 베이스라인(단일 브랜치, 단순 병합 모델, 기존 GNN 수용해도 모델)과의 구체 수치는 본문 확인 필요.

**강점**

- 예측 분해 설계 — ADME 연구에서 "이 분자의 낮은 수용해도가 작용기 때문인가, 골격 때문인가"를 직접 물을 수 있다.
- 사전학습 + 파인튜닝 전략은 소규모 데이터셋 활용에 실용적인 패턴이다.
- GNNExplainer 원자 수준 시각화는 분자 설계 피드백 루프에 활용 가능하다.

**한계**

- 코드 미공개(현재 기준).
- 덧셈 모델 가정이 비선형·고도로 얽힌 화학-구조 상호작용을 얼마나 포착하는지 불명확.
- 수용해도 단일 속성에 특화된 구조 — LogP·pKa·막투과도 같은 다른 ADME 성질로의 확장 여부는 미검증.
- `질문:` 곱셈 상호작용 항을 포함할지 결정하는 기준이 있는가, 아니면 일괄 포함하는가?
- `추정:` 데이터셋 규모가 수천 건 수준이면 GNN 학습이 불안정할 수 있으며, 이를 run-to-run 안정성 지표가 어느 정도 대리하고 있을 것이다.

**내 연구에의 적용**: 신약 초기 스크리닝 파이프라인에서 해석 가능한 ADME 예측 모듈로 활용할 수 있다. "화학 브랜치 vs. 구조 브랜치 기여 분해"는 분자 설계 방향 선택(작용기 치환 vs. 골격 변경)에 직접적인 정보를 제공한다. 코드 공개 후 AqSolDB 기반 사전학습 체크포인트를 다른 용해도 관련 과제에 전이 학습하는 실험을 시도해볼 만하다.

**검증 수준**: (in silico) — 공개 데이터셋 벤치마크.

## 방법론 흐름 메모

**이번 주 공통 패턴**

1. **해석 가능성의 설계 내장**: 성능 지표 경쟁에서 "왜 이 예측이 나왔나"로 무게중심이 옮겨가는 신호가 여러 편에서 보인다. MLP-GNN의 덧셈 분해, 구조화 GP의 불확실성 정량화, Affinage의 증거 출처 추적 — 셋 모두 사후 해석 추가가 아니라 설계 단계에서 해석 가능성을 내장했다.

2. **고차원·소표본 문제에 대한 도메인 지식 주입**: 구조화 GP(경로 커널), CNS 메틸화 분류(SRP의 차원 구조 보존), Affinage(문헌에서 실험 증거만 선별) 모두 도메인 지식을 모델 구조나 데이터 전처리 단계에 직접 주입해 데이터 효율을 높이려는 전략을 공유한다.

3. **LLM의 역할 변화**: 예측 모델이 아니라 지식 처리·추론 파이프라인의 핵심 부품으로 사용되는 패턴이 뚜렷하다(Affinage, Active-GRPO). 생물학 도메인에서 LLM은 "모델" 자체보다 "지식 추출·합성 엔진"으로 자리잡는 추세다.

4. **재현성 격차**: 5편 중 코드가 공개 확인된 것은 Affinage 1편뿐이다. 나머지 4편은 코드 미공개 상태다. 방법론적으로 흥미로운 아이디어가 많지만, 독립 재현·벤치마크 교차 검증 없이는 결과를 그대로 수용하기 어렵다. 코드 공개가 이 분야 신뢰성의 병목이다.

**내 연구 관점 우선순위**

- 즉시 활용 가능: **Affinage** (코드·데이터·API 공개, 멀티오믹스 분석 주석 레이어로 직접 사용 가능)
- 코드 공개 시 우선 확인: **구조화 GP** (소표본 오믹스 분류), **CNS 메틸화 분류** (SRP+로지스틱 회귀 파이프라인)
- 분야 동향 모니터링 대상: **Active-GRPO** (RL 분자 최적화 방법론), **MLP-GNN 수용해도** (해석 가능 ADME 예측)
